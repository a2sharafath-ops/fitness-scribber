Data, sources & calculation notes Expand supporting detail

Preview: All names, dates, outcomes and coach comments are fictional. The report window is 03–30 September 2026; the muscle map explicitly uses 21–27 September.

  • Workouts & bookings: completed workout logs and past non-cancelled appointments are separate records. “Weeks with a workout” counts four consecutive seven-day blocks beginning on 03 September. An unresolved appointment is awaiting a status update, not automatically a missed session.
  • Strength: same-lift, same-source comparisons. This example uses Epley estimates: actual load × (1 + actual reps / 30). Tested maximums and training maximums must keep their own labels. Source records remain available.
  • Muscle exposure: completed Main Lift, Accessory Lift and Power working sets only. Whole warm-up/cool-down blocks and individual warm-up sets are excluded. Direct and assisting roles come from the Exercise Library. Volume load uses actual sets × reps × external kg. Muscle totals overlap; they do not measure individual muscle force or growth. Missing load is unknown; known zero external load is not zero effort.
  • Assessments: only comparable protocols and units receive a change value. Body-measurement direction is neutral. A single record is a baseline, and a changed protocol does not produce a like-for-like trend.
  • Wellbeing: self-reported ratings with dates and denominators. No readiness or health-clearance verdict is generated. Wearable gaps remain gaps.
  • Load calculations: ACWR, monotony and strain belong in an optional coach appendix, reusing the Progress page helpers and coverage rules. No safety zones or universal thresholds are added.

Production should preserve the client route, configured units, reporting timezone and source IDs. Error or partial-load states must be labelled before export; a failed fetch must never render as zero activity.

Proposal / before implementation

A report with a clear story.

The live report was reviewed in the current build. This HTML is a separate, interactive design preview; it does not change ReportPage or write to the backend.

What needs to improve

  • The existing report leads with readiness, body measurements and full health history.
  • No completed-workout strength story, attendance visual or muscle map.
  • Resistance-only volume misses workout set data. The demo report displays 0 kg despite completed workouts.
  • Report load calculations use older logic and zero-fill missing days.
  • Long explanatory copy, fixed grids and always-visible tables make scanning difficult.

What this design changes

  • A short, data-backed story and three factual highlights.
  • Strength trends, completion calendar and muscle map.
  • Optional wellbeing and assessment comparisons.
  • Short coach note and three coach-selected next steps.
  • Details on demand; labelled units, dates and data gaps stay visible.
  • Phone layout and a printable client report.

Build after design approval

  1. Create a pure, client-scoped report data selector with a reporting period and source references.
  2. Build the report layout using shared strength, booking and muscle helpers.
  3. Add coach-selected sections and an editable report note; decide whether drafts must persist before adding storage.
  4. Add print layout and optional appendix.
  5. Test client isolation, missing/failed data, comparable baselines, units, keyboard, 390px layout and PDF breaks.

Boundaries & open decisions

  • No blocker for this preview.
  • Production needs a period picker; this preview fixes 03–30 September for a coherent example.
  • Confirm the report-specific note/draft storage approach during implementation.
  • Existing free-text goals cannot support reliable automatic progress bars.
  • Historical exercise mapping is mutable today; a reproducible saved report would need a frozen snapshot.
  • Secure sharing and scheduled delivery are separate future scope.

The optimistic sample shows observed gains. The “Starting out” example shows an encouraging baseline without invented progress. A production report should also show flat or declining comparable results neutrally and leave their interpretation to the coach. This design does not add clinical rules or pooling-engine features.
