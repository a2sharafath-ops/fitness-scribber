Schedule redesign — local testing

Open http://127.0.0.1:5178/schedule
The 5178 app remains in local builder QA mode. Nothing has been pushed or deployed.

Implemented
- Week / Day timelines, Month grid and Agenda; stable calendar and selected-day panels.
- Drag shows a full-size landing block, proposed time and duration; invalid destinations turn red.
- Bottom-edge resize, 15-minute snapping, edge scrolling, Escape cancellation and form alternative.
- Review before a move is saved. Conflicts identify the issue, link to the existing client/day and offer available slots.
- Training bookings open the matching client/date in Training; other appointment types open their relevant client section.
- Cross-day moves carry the unique client/day prescription and update its assigned-program schedule date. Exercise content, template, set IDs and other clients are preserved.
- Completed/started/past bookings and workout records are protected. Status updates remain separate from moving.
- Incomplete legacy timing is displayed explicitly; no fabricated duration is used.

Data limitations
- Existing bookings have no prescription ID. The safe link is a unique training booking plus unique prescription for that client/date. Ambiguous legacy days are blocked rather than guessed.
- This calendar books appointments; assigning a program does not automatically book appointment times.
- Recurring usual training times are not part of this version.
- Coach-time conflicts currently apply across all clients in this coach's account. Group attendance and parallel coaches do not have separate calendar resources.

Backend release requirement
Apply supabase/migrations/20261011102502_protected_schedule.sql after the existing program-library schema before deploying this UI to the connected app.
It adds save_schedule_booking, an owner-scoped SECURITY INVOKER RPC. One database transaction checks current bookings/workouts/prescriptions and writes the booking, prescription date and assigned-program date together. Existing prescription content is never upserted by this RPC.
No migration was applied to a live database. Without the RPC, connected booking updates fail safely with an installation message.
The RPC takes brief table write locks to protect against older writers. A high-volume multi-coach deployment should revisit that lock scope.
