## First complete session

1. Open **Pooling test** in the sidebar or the link above. If no workspace is shown, read the fictional-software acknowledgement, select it explicitly, then click **Create my fictional test workspace**. Otherwise reuse the displayed fictional workspace. The name is deliberately locked as fictional. Do not enroll an existing client or enter real health information.
2. Click **Prepare one fictional session** once. It confirms backend-provided software-only sources and saves unassigned drafts. Wait for the saved response and note the exact draft ID displayed. An interrupted preparation must resume with the same one/two-session choice; do not repeatedly create new scenarios.
3. Choose **Open Exercise Pool**. Inspect the current context and exact draft. You may generate a selection or swap the compatible fictional placeholder. Each revision remains unassigned and needs its own review.
4. Validate the final draft. Inspect its exact occurrence, dose, constraints and required gaps. Only a ready/current decision can be approved. Select the explicit reviewed checkbox and approve; neither preparation nor generation assigns automatically.
5. If testing daily adjustment, follow that section below **before Start**, using a separate target copy. Then open **Sessions & results** / **Open fictional client and sessions**. Find the matching approved baseline draft. Choose the current health-change answer explicitly, then start. An unknown answer or stale generation cannot start.
6. Test recording only: enter zero or a small fictional seconds value, explicitly choose the effort method `fictional-effort` if testing progression, save, pause/resume, then stop or complete. Resume requires a fresh health-change answer. Inspect saved results after refresh. Corrections append a new record with a reason; they do not erase the original zero.

## Daily adjustment and progression

- Daily adjustment: leave the approved baseline unstarted. In **Validate & approve**, expand its dated assigned row and click **Copy draft [ID] for separate review**. Note the new unassigned draft ID. In **Daily adjustment**, use its exact date and save a review question. The expanded request reveals the inputs: choose the **new copy** as Current canonical draft, the **original assignment** as baseline and `fictional-daily` as policy. Generate and inspect the exact before/after result, enter a review reason and accept if appropriate. Accept/amend creates another unassigned draft; it does not rewrite or assign the baseline. Rejection creates no replacement assignment. The assigned baseline is intentionally excluded from target choices: revalidating its source snapshot would invalidate its original approval.
- Progression: complete both baseline sets with explicit actuals and `fictional-effort`. Then prepare a later fictional session; this preserves comparable reviewed occurrence identities but still requires new source/context review. Choose `fictional-progression` and the completed baseline. Insufficient or mismatched evidence must remain a visible gap, not become an assumed result.
- Preparing another scenario changes context and may make earlier drafts/assignments stale. Finish the current journey first; do not use an old approval to bypass fresh checks.
- If an older assignment reports `source_changed`, do not keep retrying Start. Its source snapshot no longer matches its approval. Use a separate copy and fresh validation/explicit approval; retain the old history. This update prevents assigned targets in the normal UI but does not claim a backend fix for direct API revalidation of assigned drafts.

## Limits, failure and recovery

Each workspace permits at most 160 counted test writes, with normal new actions stopping at 140 to preserve capacity for results and Stop. Multiple steps can consume several writes. This is a bounded review window, not an unlimited demo or a load-test environment. Do not attempt to bypass quota or renew the window. If the limit is reached, preserve the results and report it; new capacity needs a separate scoped decision.

For an interrupted save, read **Operation recovery** and reconcile the exact saved operation before creating another. Do not clear browser storage while an outcome is unknown. Unknown or unavailable server permission must not silently fall back to a Classic action. Stop exercising immediately if relevant; confirmation that a Stop record was saved is a separate status.

**End my testing early → Revoke my test workspace** is irreversible from the UI. It stops new authority without deleting drafts/results. Do not click it until finished. It affects only your new fictional workspace, not the other coach or existing clients.

Do not change global flags, publish real content, invite users, bypass Vercel protection, call paid providers or restore an old database. If access is denied, report whether it is Vercel access or application sign-in; do not share passwords.
