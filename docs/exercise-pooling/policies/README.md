# Privacy and consent preparation pack

Package version: 0.2 (core client-facing texts remain internal drafts), 2026-09-05. INTERNAL DRAFT — NOT FOR PUBLICATION, CLIENT SIGNATURE OR RELIANCE AS LEGAL/MEDICAL ADVICE.

The user requested policies for a single coach plus a client app, with intended markets India, GCC, USA, UK and Europe. This pack provides original draft wording and implementation/review requirements. It does not certify compliance, provide clinical clearance or replace appropriate local legal/professional review.

## Proposed later implementation requirements

- Present an understandable notice before relevant collection. Participation, health-data permission and each optional purpose remain separate.
- No pre-ticked consent. Keep actual client action, notice/form version, purpose, timestamp, channel, identity, any representative authority and withdrawal history.
- Coach-entered consent requires evidence of the client's actual authorization; coach login is not client consent.
- Optional wearables, media, external AI and clinician disclosures need their specific notices/permissions where required. Core R1 pooling does not require AI or wearables.
- Proposed default: no sale, health-targeted advertising or model-training reuse. Verify existing tools/configuration before making those promises.
- Disconnection stops new authorized syncing; previously synced history, backups and lawful retention are handled separately.
- Consent cannot expand professional scope, override clinical restrictions, replace backend controls or legalize a prohibited transfer.

Remove placeholders/drafting instructions only after facts, technical controls, regional additions and reviewer approvals are complete. Keep versioned approval evidence. Nothing in this pack has been inserted into the running app.
